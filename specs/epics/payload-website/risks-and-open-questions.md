# payload-website — risks and open questions

| ID | Risk | State | Notes |
|---|---|---|---|
| PW-A | `baseline-v1` is not yet proven live | OPEN | Proven offline in Baseline CI: the offline bootstrap with the blueprint's own hooks, the lanes' own steps in staged job trees (the migrations applied through a stand-in D1 API over real SQLite), the built Worker served by `wrangler dev` — migrated, an admin signed up, the seed written to D1 and R2, the Cron Trigger run |
| PW-B | Workers Paid only | OPEN | The Worker is about 4 MiB gzipped (17.8 MiB raw): Workers Free's 3 MiB refuses it, Workers Paid's 10 MiB takes it — as Payload's own Cloudflare template says. The registry row stays unlisted until a live build on a Paid account |
| PW-C | No image resizing | ACCEPTED | sharp cannot run in a Worker: Payload keeps originals, and `next/image` serves them unoptimised. Cloudflare Images is the upgrade |
| PW-D | The schema is the migrations | ACCEPTED | A collection change is `payload migrate:create`, then `payload-sql.mjs` into a new migration. Payload's `push` is off, so a change that skips this fails loudly (a missing column), not silently |
| PW-E | The secrets live in the database | ACCEPTED | Generated by `020_app_secrets`; anyone who can read D1 can read them — the same boundary as the user table they protect. A Worker secret overrides each |
| PW-F | A webpack build | ACCEPTED | Turbopack's hashed externals break OpenNext's bundle; webpack is what Payload's Cloudflare path builds with |
| PW-G | Worker CPU limits under the admin | WATCH | The admin and the seed run under `wrangler dev`; Workers Paid allows 30 s CPU per request by default |
| PW-H | stack-tectonic 0.19.0, not 0.20.0 | ACCEPTED | 0.20.0's lane-shared install links `node_modules` out of the job's tree |
| PW-I | The template moves on `main` | ACCEPTED | `main`'s template imports an API no release exports; this port follows the release tag, and a bump is a deliberate change |
